## 目录结构

```text
Results/
├── Text_to_Code/
│   ├── Direct/
│   ├── Syntax_Constrained/
│   ├── RAG(Code)/
│   ├── RAG(Doc)/
│   └── Agent/
├── Code_to_Code/        # 五种方法子目录同上
├── Pass10/              # 十样本 Syntax-Constrained 运行（Pass@10）
├── Python/              # Python 基线评测记录
├── token_usage_text_to_code.json
└── token_usage_code_to_code.json
```

每个方法目录下，每个 `(模型, 子集)` 组合对应三个文件：

| 文件 | 内容 |
|:--|:--|
| `<model>_<subset>.jsonl` | 模型生成的 Cangjie 代码，每行一个任务（`{"id", "solution"}`） |
| `<model>_<subset>.jsonl.records.jsonl` | 单任务评测结果：`passed`、`failure_kind`、编译器与运行时的 stdout/stderr、耗时 |
| `<model>_<subset>.jsonl.summary.json` | 该 cell 的汇总：通过率、编译率、各类失败计数 |

`<subset>` 取值为 `HumanEval` 或 `ClassEval`。RAG 两种变体在文件名后追加 `_code` 或 `_doc`，标记检索语料来源。

两个 `token_usage_*.json` 给出每个 cell 的输入/输出 token 总量，对应上面的 token 成本图。

### Pass@10

`Pass10/` 存放论文 discussion 部分的十样本 Syntax-Constrained 运行结果，命名略有不同：

| 文件 | 内容 |
|:--|:--|
| `<model>_<subset>_10samples_concurrent.jsonl` | 每个任务 10 个生成样本 |
| `<model>_<subset>_pass10.records.jsonl` | 每个样本的评测结果 |
| `<model>_<subset>_pass10.summary.json` | Pass@10 / Pass@1 率以及 token 统计 |

`timeout_rerun_results.json` 记录首次评测中触发超时、被重跑的少量样本。

所有 `summary.json` 中的文件路径都是相对于本 `Results/` 目录的相对路径。
